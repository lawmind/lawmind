## 0. HOW TO READ THE NUMBERS HERE

Every figure carries four things, because a number without them is the thing that
made this round necessary: **when it was measured, what population it divides,
where it came from, and whether it is live.**

| label | meaning |
| --- | --- |
| `LIVE` | queried from the database or the host during this round |
| `SNAPSHOT` | a receipt written by a tool run during this round |
| `CARRIED_FORWARD` | an earlier accepted value, re-read but **not** re-measured |

**No roadmap number is restated as current anywhere in this file.** Where an
earlier figure and a current one differ, both appear.

Two clocks are in play and they are four hours apart. Database and receipt
timestamps are **UTC**. Windows Task Scheduler timestamps are **local (UTC+04:00)**.
Where a scheduler time appears it is marked `local`.

### Why there is no single completeness percentage in this file

`ACCOUNTED / 20,239,701 = 94.02%` is computable and is **not** reported as a
coverage figure. The denominator 20,239,701 is `CARRIED_FORWARD_NOT_REMEASURED`
(perCourtPerYear, 20 Aug 2026) and it counts **upstream parquet rows, not
documents** — several rows can describe one document and some describe none. A
percentage over that denominator is a lower bound on an unknown quantity, not
corpus coverage, and collapsing held / unavailable / failed into it is exactly
what §3 of this round's instruction forbids.

The correct completeness signal is the walk frontier, not a subtraction:


The newest checkpoint write (16:16Z) is **later** than the newest successful
ingest (14:13Z). The walker advanced offsets for two more hours while producing no
canonical rows — consistent with it walking into `pdf_absent`/`no_text` territory
and ledgering refusals, which is the designed behaviour and not a stall.

### A finding: `cited_authority` has drifted, and the snapshot hash cannot see it

`cited_authority` is a **materialised view** (`SELECT DISTINCT cited_judgment_id …`).
It is joined into `judgment_embedding_eligibility` as the `is_cited_authority`
axis, which can rescue a document from a refusing semantic tier.

**Measured `2026-09-18T19:59Z`, 64 ms. State: LIVE.**

```text
matview_rows          35,890
live_rows             35,364
in_matview_not_live      826   <- no longer cited by any row
in_live_not_matview      300   <- newly cited, invisible to the eligibility axis
symmetric difference   1,126
```

Why this is worth writing down: `SNAPSHOT_HASH` is
`sha256(pg_get_viewdef('judgment_embedding_eligibility'))` — it hashes the view's
**definition**. A matview the definition joins to can drift arbitrarily far in its
**contents** while the hash stays byte-identical. The contract identity check is
sound for what it checks and is blind to this.

Bounded impact: up to 300 documents may be excluded from eligibility that the
current citation graph would admit. That is 0.0039% of the 7.68M eligible content
identities, and the census accounting still closes exactly (§7), so it is a
coverage question and not an integrity one. **No refresh was performed** — a
`REFRESH MATERIALIZED VIEW` is a write and would move the eligibility population.
Raised as `DATA_CONTINUITY_3`.
