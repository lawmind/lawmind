## Open questions

### OQ-1 — §10a render index does not cover renders 44–63 · OPEN
`design/screens/IMPLEMENTATION.md` §10a still reads "30-43 are current" and lists nothing above
43. Twenty authoritative renders — including every screen that closed a NOT YET
DESIGNED item, plus the micro-typography, glass and gilt specs — are absent from
the index that declares which PNGs to build from. The mapping above and
`design/screens/SCREENS.md` cover it in the meantime. Not invented into §10a,
which is a design deliverable.

### OQ-2 — is "magic link sent" obsolete or pending? · OPEN
The only `NOT YET DESIGNED` row. PD-1 settles SMS OTP, and the OTP screen is
drawn. If PD-1 is complete, row 3 should be struck rather than drawn — but that is
a screen-list edit on a design deliverable, so it is flagged, not made.

### OQ-3 — PD-6 says two immediate-push exceptions, §9b #8 says one · OPEN
PD-6: `set_aside` on a citation in an **exported** draft, **and** a newly
discovered listing for **tomorrow**. §9b #8: "the single exception is an authority
set aside that is cited in tomorrow's hearing". `PRODUCT_DECISIONS.md` is
authority and is what `docs/API_CONTRACTS.md` implements.

### OQ-4 — sign-in appears twice, on two different auth methods · OPEN
Row 2 (`10d`, `design/screens/renders/44-splash-signin@2x.png`) shows sign-in by **enrolment number**;
row 73 (`11a`, `design/screens/renders/58-signin-otp@2x.png`) shows **SMS OTP**. PD-1 settles OTP, so
row 2's second frame is superseded. The splash itself (row 1, same render) is
current.
